# 股票底部预测（功能二）· 口径与实现

对应脚本：`scripts/bottom_forecast_tushare.py`，入口 `scripts/bottom.sh`。

## 一、算什么

对股票池里每一只，用**目标交易日的日线 + 当天 1 分钟线**算出 8 个价位 + 3 个辅助字段：

| 列 | 来源 | 含义 |
|---|---|---|
| `p_close` | 日线（前一日收盘） | 前收 |
| `open` / `close` | 日线 | 今开 / 今收 |
| `high` / `low` | **分钟线**极值 | 当日最高 / 最低（分钟口径） |
| `high_after_low` | 分钟线 | 最低点之后的最高点 |
| `low_after_high` | 分钟线 | 最高点之后的最低点 |
| `hc` `hd` `hx` → `ha` | 公式 | 压力位（均值 = 压力中枢） |
| `lc` `ld` `lx` → `la` | 公式 | 支撑位（均值 = 支撑中枢） |
| `no` | 公式 | 平盘价 |
| `ma20` | 日线 | 20 日均线 |
| `signal_strength` | 公式 | `lx < ma20×0.85` → `weak`（风险提示，非买卖建议） |

公式（与聚宽原版、腾讯免费版逐字一致）：

```
hc = c_high / p_close * close        hd = c_high / open * close
hx = high_after_low / c_low * close  ha = (hc + hd + hx) / 3
lc = c_low / open * close            ld = c_low / p_close * close
lx = low_after_high / c_high * close la = (lc + ld + lx) / 3
no = open / p_close * close          signal = lx < ma20*0.85 ? weak : normal
```

注意：**`c_high` / `c_low` 取日线**，而 `high` / `low` 列以及 `low_after_high` /
`high_after_low` 取**分钟线**——这是原版循环内的取值方式，不是笔误。

## 二、数据来源

| 数据 | Tushare 接口 | 取法 |
|---|---|---|
| 股票日线 | `daily` | 按 `trade_date` **整市场一次**（约 5600 行/次） |
| ETF/基金日线 | `fund_daily` | 按 `ts_code` 列表 + 区间 **批量一次** |
| 1 分钟线 | `stk_mins` | 按 `ts_code` 列表批量，**30 只/批** |
| 交易日历 | `trade_cal` | 按自然年缓存 |

`daily` 不覆盖 ETF，所以池子里的 28 只 ETF 走 `fund_daily`；`stk_mins` 本身支持 ETF。

## 三、口径

1. **不复权**：`daily` / `fund_daily` / `stk_mins` 都是不复权价。
2. **成交量量纲**：`daily`/`fund_daily` 的 `vol` 是「手」，×100 折成「股」后与
   `stk_mins.vol`（股）比较，放量判据 `分钟量 > 5日均量×1.5`。
3. **241 根不裁剪**：`stk_mins` 每日返回 241 根（含 09:30 集合竞价）。实测裁成 240 根
   极值不变，保留全部——集合竞价是真实成交，日线高低点也含它，保留才和日线自洽。
4. **极值位置取最后一次出现**（等价原版 `tail(1)`）。
5. 所有输出 `round(2)`；Tushare 价格带浮点尾数（如 `5.470000000000003`），不影响结果。

> 自洽性验证：本版「分钟最高价 == 日线最高价」在 2026-11-19 的 666 只里达到
> **664/666（99.7%）**，说明分钟数据完整；早期用腾讯免费接口的版本只有 53%。

## 四、缓存分层

| 数据 | 缓存键 | TTL | 每天要不要重取 |
|---|---|---|---|
| 历史 `daily` | `(接口, trade_date)` | 永久 | 否 |
| 历史 `fund_daily` | 完整参数（含代码列表+区间） | 永久 | 否 |
| 历史 `stk_mins` | `(ts_code, 当日区间)` | 永久 | 否 |
| **当日**的以上三类 | 同上 | **6 小时** | **是** |
| `trade_cal` | 自然年 | 30 天 | 否 |

结论：**每天必须新取的只有「目标交易日的日线 + 当天每股 1 分钟线」**；
`ma20`、5 日均量、前收所需的 20 个历史交易日全部命中缓存。

实测（2026-11-19，666 只）：

| 场景 | HTTP 请求 | 缓存命中 | 耗时 |
|---|---:|---:|---:|
| 全量首跑（冷缓存） | ≈49 | 0 | 数分钟（受网关限流） |
| 全量同日重跑 | **0** | 695 | **≈1 s** |
| 隔日重跑 | ≈25 | 其余全中 | 数分钟 |

磁盘代价：`stk_mins` 约 22 KB/只/日 → 全量约 **15 MB/交易日**，注意定期清理。

## 五、性能要点

- **日线按交易日批量**：算 `ma20` 只要 25 次调用，逐只要 666 次。
- **ETF 批量 + 区间**：28 只 ETF 1 次调用（别按交易日拉整市场 ETF 日线）。
- **分钟线多代码批量**：`stk_mins` 的 `ts_code` 支持逗号分隔，但网关有 **8000 行上限**
  （40 只 → 截断成 216 根/只），故 30 只/批（30×241=7230 行），
  漏码或触顶自动退化单只重取。**668 只从 668 次降到 23 次。**

## 六、限制与排错

| 现象 | 原因 / 处理 |
|---|---|
| `您请求速度过快` / `请不要超过10个线程` | 网关限流，脚本按 20/40/60s 退避；不要并发跑多实例 |
| 大量「无当日分钟线」 | 网关未开通「A股历史分钟」(stk_mins) 权限 |
| ETF 整行是 0 | `fund_daily` 无权限或接口异常，看日志里的 ⚠ |
| 某只 ma20 与其他源不一致 | 该股窗口内停牌，历史窗口起点不同，属取数差异 |
| 只有最近 1~2 天能算 | 不会发生：`stk_mins` 支持任意历史日期，`--date` 可回算 |
| 结果行数是 0 | 当天不是交易日，或 `--date` 落在非交易日 |

缓存全在 `$DIVIDEND_SCREEN_HOME/data/cache/`，可随时整体删除重建。

## 七、参数速查

| 参数 | 作用 |
|---|---|
| `--date YYYY-MM-DD` | 目标交易日；默认自动判定（盘中 <15:00 回滚到前一交易日） |
| `--codes A,B` | 只跑指定代码（6 位或 ts_code） |
| `--limit N` / `--offset N` | 只跑前 N 只 / 跳过前 N 只 |
| `--history-days N` | 往前取多少个交易日算 ma20（默认 40） |
| `--background` | 仅 `bottom.sh` 支持，后台跑并返回日志路径 |
| `--refresh` | 忽略所有缓存重新取数 |
| `--no-cache` | 完全不读不写缓存 |
| `--interval` / `--retries` | 请求最小间隔（默认 0.35s）/ 重试次数 |
| `-v` / `-q` | 逐股明细 / 静默 |
